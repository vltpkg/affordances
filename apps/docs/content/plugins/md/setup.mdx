---
title: Setup
description: Add the md plugin to your Next.js config, then the route handler that renders and converts pages.
---

With the Affordances graph, add `md()` to `withAffordances`'s plugins:

```ts title="next.config.ts"
import { withAffordances } from '@affordances/next/config'
import { md } from '@affordances/md/next'

export default withAffordances(nextConfig, { name: 'Store', plugins: [md()] })
```

On its own, wrap the config with `withMd`:

```ts title="next.config.ts"
import { withMd } from '@affordances/md/next'

export default withMd(nextConfig)
```

Then add the route handler. `init` writes it:

<Run cmd="@affordances/md init" />

It's one line:

```ts title="app/api/affordances/md/[[...path]]/route.ts"
export { GET } from '@affordances/md/next'
```

## Routing

The config only adds rewrites and headers, so nothing runs per request until an agent asks:

- A page requested with `Accept: text/markdown` is rewritten to the handler. API routes, `/_next`, and Next's own client navigations (the `RSC` header or `_rsc` param) are left alone. A dot in the path is fine, so `/version/5.3.0` and `/package/chart.js` work; a file in `public/` asked for this way comes back as itself, since the handler passes anything that isn't HTML through.
- `/blog/post.md` and `/index.md` (for `/`) are rewritten after Next's own files, so a real `.md` file in `public/` still wins. Like all of Next's matching, `.MD` works too.
- The handler's own request for the page carries an `x-affordances-md-render` header, which the rewrites skip, so it can't loop.

Next matches `Accept` as a pattern, so a header that lists `text/markdown` with a low q-value still gets Markdown. Browsers never send it, so in practice only agents do.

### Pages whose URL ends in .md

On some routes a page's own URL can end in `.md`: a package registry has a package named `readme.md`, so `/package/readme.md` is a page, while `/package/express.md` is the twin of `/package/express`. List those routes as Next sources, and the handler tells them apart by asking for the page:

```ts title="next.config.ts"
export default withMd(nextConfig, { literalMd: ['/package/:name'] })
```

They're matched the way Next matches a rewrite's `source` (named and unnamed params, patterns, `{}` groups, `?` `*` `+`), and a source Next would reject throws when the config loads. They're matched against the URL as it was requested, like the rewrites they feed: for a public URL an [alias](#public-urls-your-proxy-maps-onto-routes) maps onto a route, list its public shape (`'/package/@:scope/:name'`), not the route's.

For a URL on those routes that ends in `.md`, the handler first fetches the page at that exact URL:

- If it answers with anything but a 404, it's the page. A request for Markdown (`Accept: text/markdown`) gets it converted; any other request gets the page's HTML as it came. A redirect, a 401, or a 500 counts as an answer, so an error is never hidden behind a twin.
- If it 404s, the `.md` is the twin suffix, and the request gets the Markdown of the URL without it. So `/package/readme.md.md` is the Markdown of the page `readme.md`.

The twin of any page is still its URL plus `.md`, so links, `Link` headers and `llms.txt` don't change. The page needs to 404 for a name it doesn't have (`notFound()`), not render a 200 "not found" page. Each twin request on these routes costs that 404 render before the real one; routes not listed make one request, as before.

## Public URLs your proxy maps onto routes

A route whose public URL isn't its folder's needs `md()` told about it once. A registry serves `/package/@babel/core`, and its `proxy.ts` (or a rewrite) sends it to `app/package/[pkg]` as `/package/@babel%2Fcore`. Give `md()` the same mapping as `aliases`, in Next's rewrite syntax: the public source, then the URL it's sent to.

```ts title="next.config.ts"
import { withMd } from '@affordances/md/next'

export default withMd(nextConfig, {
  aliases: {
    '/package/@:scope/:name/:rest*': '/package/@:scope%2F:name/:rest*',
  },
})
```

Then the public URL gets everything a page's own URL does:

- a `Link` header: `/package/@babel/core/versions` points at `/package/@babel/core/versions.md`;
- twin links: the converted Markdown links `/package/@babel/core/versions` as its `.md`;
- its route's [`markdown.ts`](/docs/plugins/md/markdown-file), with `params` exactly as `page.tsx` gets them for that URL: `{ pkg: '%40babel%2Fcore' }`, still encoded;

An alias doesn't route anything. Your proxy or rewrite still sends the page there; the alias tells `md()` what it does, so keep the two in step.

- Each alias is checked when the config loads. One whose destination no page in `app/` answers throws, quoting the alias and naming the nearest pages, so a typo fails `next dev` and `next build`, not a request.
- The first alias that matches a URL wins, in the order you list them, before the URL is matched against `app/` as it is.
- Name every param in a source (`:id(\d+)`, not `(\d+)`): Next leaves unnamed params out of a header's values, so a source with one gets no `Link` header, and `md()` says so when the config loads.
- It's matched the way Next routes a page: case-sensitively and with no empty segment. `/Package/@babel/core.md` gets the page's HTML converted, never `markdown.ts`.
- The handler reads it against the URL that was requested, which is the URL your proxy gated, so nothing a request sends can choose a route. A request made straight to `/api/affordances/md/…` still never runs a `markdown.ts`.

## Advertise it

Every page answers with a `Link` header pointing at its Markdown twin, so an agent that fetched the HTML can find it:

```http
Link: </blog/post.md>; rel="alternate"; type="text/markdown"
```

`md()` finds your pages in `app/` when Next loads the config, so a page added during `next dev` gets its header after a restart. On an Affordances site, the value is added to the graph's own `Link` header. Turn it off with `md({ link: false })`, and point it at another project root with `md({ root })`.

For a `<link>` element in the HTML as well, `mdAlternate(path)` returns metadata alternates for a page's Markdown twin:

```ts title="app/blog/[slug]/page.tsx"
import { mdAlternate } from '@affordances/md/next'

export const generateMetadata = async ({ params }) => {
  const { slug } = await params
  return { alternates: { canonical: `/blog/${slug}`, ...mdAlternate(`/blog/${slug}`) } }
}
```

That renders `<link rel="alternate" type="text/markdown" href="/blog/post.md">`. For `/`, it points at `/index.md`.

## With a proxy.ts

Next runs `proxy.ts` (or `middleware.ts`) before any rewrite, so a proxy that treats Markdown requests differently, to skip a locale redirect or an A/B rewrite, needs the same match the rewrites make. Don't copy it: `isMdRequest` and `mdRewrite` are that match, including Next's case-insensitive paths. Import them (and `mdLink`) from `@affordances/md/next/proxy`, which holds only the matching, so your proxy's bundle carries neither the converter nor any `markdown.ts`; `@affordances/md/next` exports the same functions.

**Never skip your auth gate for Markdown requests.** Run it first, then route Markdown:

```ts title="proxy.ts"
import { NextResponse, type NextRequest } from 'next/server'
import { isMdRequest } from '@affordances/md/next/proxy'

export const proxy = (request: NextRequest) => {
  // your gate, first: a Markdown request is a request for the page
  if (!request.cookies.has('session')) return NextResponse.redirect(new URL('/login', request.url))
  // then what's only for Markdown, such as skipping a locale redirect
  if (isMdRequest(request)) return NextResponse.next()
  // …the rest of your proxy
}
```

The proxy runs once, on the URL that was requested: `/dashboard/1.md`, or `/dashboard/1` with `Accept: text/markdown`. For a page converted from its HTML, the handler's own request for the page goes through the proxy again, but a route with a [`markdown.ts`](/docs/plugins/md/markdown-file) isn't rendered, so that first run is its only gate. With 0.1.0's recipe, which returned early for Markdown requests, remove that skip before adding a `markdown.ts`.

Your proxy's matcher has to match a page's `.md` URL as well as the page. `'/dashboard/:path*'` covers `/dashboard/123.md`, but `'/dashboard/:id(\\d+)'` doesn't: the `.md` URL slips past the gate. Add `'/dashboard/:id(\\d+).md'` to the matcher, or run the gate-first recipe above with no `matcher` at all. The handler never runs a `markdown.ts` for a request made straight to its own URL (`/api/affordances/md/…`), which a proxy matcher scoped to your pages wouldn't see; that gets the page's HTML render, gated at the page's URL.

`mdRewrite(request)` returns the handler URL the request would be rewritten to, or `undefined`, for a proxy that rewrites it itself: `NextResponse.rewrite(url)`. A proxy can't see `public/`, so a real `.md` file there matches too.

Next hides a client navigation's `RSC` header and `_rsc` param from the proxy, so there `mdRewrite` can't tell one from a page request. Next puts the header back before the handler runs, so the handler passes such a request through: it fetches the page with the request's own headers and returns the page's RSC payload as it came (status, headers, and body), never markdown. With `skipProxyUrlNormalize: true` in `next.config`, the proxy sees them and `mdRewrite` leaves the request alone, like the rewrites do.

### Link from the proxy

`md()` sets the `Link` header by matching your `app/` routes against the URL as it was requested. A route whose public URL isn't its folder's, one your proxy rewrites, gets no header: `/package/@babel/core` has two segments, but `app/package/[pkg]` matches one. [`aliases`](#public-urls-your-proxy-maps-onto-routes) fix that once for the header, twin links and `markdown.ts`, so a site with them doesn't need `mdLink`. Without them, `mdLink(request)` returns the `Link` value for the request's public URL, or `undefined` for anything that isn't a page request (API routes, `/_next`, `.md` URLs, Markdown and RSC requests):

```ts title="proxy.ts"
import { NextResponse, type NextRequest } from 'next/server'
import { mdLink, mdRewrite } from '@affordances/md/next/proxy'
// your own rewrite: /package/@scope/name → the URL app/package/[pkg] answers, or undefined
import { route } from './route'

export const proxy = (request: NextRequest) => {
  const markdown = mdRewrite(request)
  if (markdown) return NextResponse.rewrite(markdown)

  const url = route(request.nextUrl)
  if (!url) return NextResponse.next()
  const response = NextResponse.rewrite(url)
  const link = mdLink(request)
  if (link) response.headers.set('Link', link)
  return response
}
```

A `Link` the proxy sets replaces the one `md()` sets for the same URL, rather than adding to it, and that includes an Affordances graph's `rel="affordances"` value. Call `mdLink` only for the URLs `md()`'s rules miss, as above, or join the values yourself.
