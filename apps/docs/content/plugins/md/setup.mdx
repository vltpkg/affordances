title: Setup
description: Add the md plugin to your Next.js config, then the route handler that renders and converts pages.
---

It needs Next.js 16 or later, with the App Router. `partialPrefetching` is a Next 16.3 option; the rest, `cacheComponents`, `cacheLife` profiles, `forbidden()` and `unauthorized()`, and `proxy.ts`, works from 16.0.

With the Affordances graph, add `md()` to `withAffordances`'s plugins:

```ts title="next.config.ts"
import { withAffordances } from '@affordances/next/config'
import { md } from '@affordances/md/next'

export default withAffordances(nextConfig, { name: 'Store', plugins: [md()] })
```

On its own, wrap the config with `withMd`:

```ts title="next.config.ts"
import { withMd } from '@affordances/md/next'

export default withMd(nextConfig)
```

Then add the route handler. `init` writes it, and adds `.affordances/**/*.ts` to your `tsconfig.json`'s `include`, so `tsc` checks each [`markdown.ts`](/docs/plugins/md/markdown-file) against its route (commit both):

<Run cmd="@affordances/md init" />

It's one line:

```ts title="app/api/affordances/md/[[...path]]/route.ts"
export { GET } from '@affordances/md/next'
```

The route is your file, as any route in `app/` is. To change how it converts, replace the line with `createMdHandler` and its options:

```ts title="app/api/affordances/md/[[...path]]/route.ts"
import { createMdHandler } from '@affordances/md/next'

export const GET = createMdHandler({ maxBytes: 32 * 1024 * 1024, timeout: 20_000 })
```

- `maxBytes`, 16 MiB by default: the most of a page's HTML it keeps to convert, a memory guard. Next's Flight data (the payload a page hydrates from, and with `partialPrefetching` most of a big page's bytes) doesn't count: it's read for its error rows as the page streams and never kept, so a 30 MB `partialPrefetching` page converts with the default. The whole response, Flight data and all, can be up to 8 times `maxBytes`. A page past either answers `413` saying so, and the server logs which page and the line to change, so a page that grows (a report, a changelog) is caught when it crosses it.
- `timeout`, 10 seconds by default: how long the page has to stream. A page still streaming then is converted as far as it got and marked partial; one that sent nothing answers `504`.

The rest of its options (`origin`, `headers`, `append`, `linkTwins`) are in [Caching and privacy](/docs/plugins/md/caching).

The handler fetches each page from the request's own origin. `next start` builds that from its own hostname and port, never from the `Host` header, so a caller can't point it at another server. With `experimental.trustHostHeader` (Vercel sets it, behind its own edge) or a custom server, `Host` decides it: behind a proxy of your own that passes `Host` through, set `AFFORDANCES_MD_ORIGIN` to the URL the server reaches itself at, such as `http://localhost:3000`.

## Routing

The config only adds rewrites and headers, so nothing runs per request until an agent asks:

- A page requested with `Accept: text/markdown` is rewritten to the handler. API routes, `/_next`, and Next's own client navigations (the `RSC` header or `_rsc` param) are left alone. A route handler there (a `route.ts` such as `app/llms.txt/route.ts`, or a Next metadata route such as `sitemap.ts` or `opengraph-image.tsx`) is passed through as it is, with the caller's own headers: the handler ranks `md()`'s pages and route handlers as Next does, so `/og/about` is a page beside `app/og/[slug]/route.ts`, and a catch-all `route.ts` takes only the paths no page has. A route handler's path is never twinned in a link. A dot in the path is fine, so `/version/5.3.0` and `/package/chart.js` work; a file in `public/` asked for this way comes back as itself, since the handler passes anything that isn't HTML through.
- `/blog/post.md` and `/index.md` (for `/`) are rewritten after Next's own files, so a real `.md` file in `public/` still wins. Like all of Next's matching, `.MD` works too.
- The handler's own request for the page carries an `x-affordances-md-render` header, which the rewrites skip, so it can't loop.

Next matches `Accept` as a pattern, so a header that lists `text/markdown` with a low q-value still gets Markdown. Browsers never send it, so in practice only agents do.

### Pages whose URL ends in .md

On some routes a page's own URL can end in `.md`: a package registry has a package named `readme.md`, so `/package/readme.md` is a page, while `/package/express.md` is the twin of `/package/express`. List those routes as Next sources, and the handler tells them apart by asking for the page:

```ts title="next.config.ts"
export default withMd(nextConfig, { literalMd: ['/package/:name'] })
```

They're matched the way Next matches a rewrite's `source` (named and unnamed params, patterns, `{}` groups, `?` `*` `+`), and a source Next would reject throws when the config loads. They're matched against the URL as it was requested, like the rewrites they feed: for a public URL an [alias](#public-urls-your-proxy-maps-onto-routes) maps onto a route, list its public shape (`'/package/@:scope/:name'`), not the route's.

For a URL on those routes that ends in `.md`, the handler first fetches the page at that exact URL:

- If it answers with anything but a 404, it's the page. A request for Markdown (`Accept: text/markdown`) gets it converted; any other request gets the page's HTML as it came. A redirect, a 401, or a 500 counts as an answer, so an error is never hidden behind a twin.
- If it 404s, the `.md` is the twin suffix, and the request gets the Markdown of the URL without it. So `/package/readme.md.md` is the Markdown of the page `readme.md`.

The twin of any page is still its URL plus `.md`, so links, `Link` headers and `llms.txt` don't change. The page needs to 404 for a name it doesn't have (`notFound()`), not render a 200 "not found" page. Each twin request on these routes costs that 404 render before the real one; routes not listed make one request, as before.

## Public URLs your proxy maps onto routes

A route whose public URL isn't its folder's needs `md()` told about it once. A registry serves `/package/@babel/core`, and its `proxy.ts` (or a rewrite) sends it to `app/package/[pkg]` as `/package/@babel%2Fcore`. Give `md()` the same mapping as `aliases`, in Next's rewrite syntax: the public source, then the URL it's sent to.

```ts title="next.config.ts"
import { withMd } from '@affordances/md/next'

export default withMd(nextConfig, {
  aliases: {
    '/package/@:scope/:name/:rest*': '/package/@:scope%2F:name/:rest*',
  },
})
```

Then the public URL gets everything a page's own URL does:

- a `Link` header: `/package/@babel/core/versions` points at `/package/@babel/core/versions.md`;
- twin links: the converted Markdown links `/package/@babel/core/versions` as its `.md`;
- its route's [`markdown.ts`](/docs/plugins/md/markdown-file), with `params` exactly as `page.tsx` gets them for that URL: `{ pkg: '%40babel%2Fcore' }`, still encoded;

An alias doesn't route anything. Your proxy or rewrite still sends the page there; the alias tells `md()` what it does, so keep the two in step, or have the proxy map with [`mdAliasPath`](#with-a-proxyts) so there's one table.

- Each alias is checked when the config loads. One whose destination no page in `app/` answers throws, quoting the alias and naming the nearest pages, so a typo fails `next dev` and `next build`, not a request.
- The first alias that matches a URL wins, in the order you list them, before the URL is matched against `app/` as it is.
- Name every param in a source (`:id(\d+)`, not `(\d+)`): Next leaves unnamed params out of a header's values, so a source with one gets no `Link` header, and `md()` says so when the config loads.
- It's matched the way Next routes a page: case-sensitively and with no empty segment. `/Package/@babel/core.md` gets the page's HTML converted, never `markdown.ts`.
- The handler reads it against the URL that was requested, which is the URL your proxy gated, so nothing a request sends can choose a route. A request made straight to `/api/affordances/md/…` still never runs a `markdown.ts`.

## Advertise it

Every page answers with a `Link` header pointing at its Markdown twin, so an agent that fetched the HTML can find it:

```http
Link: </blog/post.md>; rel="alternate"; type="text/markdown"
```

`md()` finds your pages in `app/` when Next loads the config, so a page added during `next dev` gets its header after a restart. On an Affordances site, the value is added to the graph's own `Link` header. Turn it off with `md({ link: false })`, and point it at another project root with `md({ root })`.

For a `<link>` element in the HTML as well, `mdAlternate(path)` returns metadata alternates for a page's Markdown twin:

```ts title="app/blog/[slug]/page.tsx"
import { mdAlternate } from '@affordances/md/next'

export const generateMetadata = async ({ params }) => {
  const { slug } = await params
  return { alternates: { canonical: `/blog/${slug}`, ...mdAlternate(`/blog/${slug}`) } }
}
```

That renders `<link rel="alternate" type="text/markdown" href="/blog/post.md">`. For `/`, it points at `/index.md`.

## With a proxy.ts

Next runs `proxy.ts` (or `middleware.ts`) before any rewrite, so a proxy with gates (sign-in, feature flags, a paywall) has to gate Markdown requests too: `/dashboard.md` and `/dashboard` asked for with `Accept: text/markdown` are requests for the dashboard. `mdProxy(request)` gives every gate the page a request is for, so the shortest proxy is the safe one:

```ts title="proxy.ts"
import type { NextRequest } from 'next/server'
import { mdProxy } from '@affordances/md/next/proxy'

export const proxy = (request: NextRequest) => {
  const md = mdProxy(request)
  // your gates, first, on md.page: /dashboard.md and /dashboard with Accept are both /dashboard
  if (md.page.pathname.startsWith('/dashboard') && !request.cookies.has('session'))
    return md.redirect(new URL('/sign-in', request.url))
  return md.next()
}
```

- `md.page` is a `URL`: the page the request is for, HTML or Markdown alike. `/compare.md` is `/compare`, `/index.md` is `/`, and a [`literalMd`](#pages-whose-url-ends-in-md) page keeps its own `.md`, since the handler tells which it is. It has the request's search. Run every gate on it.
- `md.markdown` says whether the request is for Markdown.
- `md.redirect(url, status?)` is `NextResponse.redirect`, except that a Markdown request sent to a page on this site goes to that page's `.md` (`/sign-in.md?…`), so an agent stays in Markdown. Another origin gets a plain redirect, never a `.md`. A Markdown request's redirect is `private, no-store` and varies on `Accept`.
- `md.rewrite(destination, init?)` is `NextResponse.rewrite`, except that a Markdown request gets the destination page's Markdown, with `init.status`: a flag gate's `md.rewrite(new URL('/404', request.url), { status: 404 })` answers with the `404` page's Markdown. It's `private, no-store` and varies on `Accept`. Another origin, and a page request, get Next's own rewrite.
- `md.next(init?)` lets the request through: a Markdown request to the handler, any other with `NextResponse.next(init)`.
- `md.request` is the page as a `NextRequest`, with the request's method, headers and cookies, for a gate that takes a request rather than a URL (a middleware's route matcher).
- `md.adopt(response)` makes a response from a middleware you didn't write right for a Markdown request: its redirect to a page on this site goes to that page's `.md`, its rewrite to a page on this site gives that page's Markdown with the response's status, its `NextResponse.next()` goes on to the handler, and anything else it answers is made `private, no-store`. The cookies it set go along. Another origin, and any request that isn't for Markdown, get the response as it came, so it's safe on every path.
- `md.link` is the page's `Link` value, for a site that maps URLs onto routes without [`aliases`](#public-urls-your-proxy-maps-onto-routes); see [below](#link-from-the-proxy).

`md.redirect`, `md.rewrite` and `md.next` are for gates you write. `md.adopt` is for a response from a third-party middleware, gating `md.request`:

```ts title="proxy.ts"
import type { NextFetchEvent, NextRequest } from 'next/server'
import { mdProxy } from '@affordances/md/next/proxy'
import { authMiddleware } from './auth'

export const proxy = async (request: NextRequest, event: NextFetchEvent) => {
  const md = mdProxy(request)
  const answer = await authMiddleware(md.request, event)
  return answer ? md.adopt(answer) : md.next()
}
```

`mdAliasPath(pathname)` is the app route URL a public URL renders through [`aliases`](#public-urls-your-proxy-maps-onto-routes), as the handler resolves it, or the pathname as it is, for a proxy that maps the same URLs and wants one source of truth.

Import it from `@affordances/md/next/proxy`, which holds only the matching, so your proxy's bundle carries neither the converter nor any `markdown.ts`. `@affordances/md/next` exports the same functions.

A proxy that also rewrites (a locale, an A/B test, URLs it maps onto routes) runs its gates, sends Markdown on, then does its own work:

```ts title="proxy.ts"
import { NextResponse, type NextRequest } from 'next/server'
import { mdProxy } from '@affordances/md/next/proxy'
// your own: whether the visitor may see a flagged page, and /package/@scope/name → the URL app/package/[pkg] answers
import { collapse, flagOn, isFlagged } from './site'

export const proxy = (request: NextRequest) => {
  const md = mdProxy(request)
  if (isFlagged(md.page.pathname) && !flagOn(request)) return md.redirect(new URL('/', request.url))
  if (md.markdown) return md.next()
  const url = collapse(request.nextUrl)
  return url ? NextResponse.rewrite(url) : NextResponse.next()
}
```

The proxy runs once, on the URL that was requested: `/dashboard/1.md`, or `/dashboard/1` with `Accept: text/markdown`. For a page converted from its HTML, the handler's own request for the page goes through the proxy again, but a route with a [`markdown.ts`](/docs/plugins/md/markdown-file) isn't rendered, so that first run is its only gate. With 0.1.0's recipe, which returned early for Markdown requests before its gates, remove that skip before adding a `markdown.ts`.

Your proxy's matcher has to match a page's `.md` URL as well as the page, its root included:

```ts title="proxy.ts"
export const config = {
  // the dashboard, its pages, and each one's .md twin: /dashboard.md isn't under /dashboard/
  matcher: ['/dashboard', '/dashboard.md', '/dashboard/:path*'],
}
```

`'/dashboard/:path*'` covers `/dashboard/123.md`, but not `/dashboard.md`, the twin of `/dashboard` itself: without `'/dashboard.md'` in the list, `app/dashboard/markdown.ts` runs ungated there. A matcher that names a page's exact shape (`'/dashboard/:id(\\d+)'`) misses its `.md` URL (`/dashboard/123.md`) too; add `'/dashboard/:id(\\d+).md'`. Or run the gate-first recipe above with no `matcher` at all, which covers every shape. The handler never runs a `markdown.ts` for a request made straight to its own URL (`/api/affordances/md/…`), which a proxy matcher scoped to your pages wouldn't see; that gets the page's HTML render, gated at the page's URL.

`mdProxy` is built on two lower-level functions, which stay: `isMdRequest(request)` is `md.markdown`, and `mdRewrite(request)` returns the handler URL a Markdown request goes to, or `undefined`, for a proxy that rewrites it itself. A proxy can't see `public/`, so a real `.md` file there matches too.

Next hides a client navigation's `RSC` header and `_rsc` param from the proxy, so there `mdRewrite` can't tell one from a page request. Next puts the header back before the handler runs, so the handler passes such a request through: it fetches the page with the request's own headers and returns the page's RSC payload as it came (status, headers, and body), never markdown. With `skipProxyUrlNormalize: true` in `next.config`, the proxy sees them and `mdRewrite` leaves the request alone, like the rewrites do.

### Link from the proxy

`md()` sets the `Link` header by matching your `app/` routes against the URL as it was requested. A route whose public URL isn't its folder's, one your proxy rewrites, gets no header: `/package/@babel/core` has two segments, but `app/package/[pkg]` matches one. [`aliases`](#public-urls-your-proxy-maps-onto-routes) fix that once for the header, twin links and `markdown.ts`, so a site with them doesn't need `mdLink`. Without them, `md.link` (or `mdLink(request)`) is the `Link` value for the request's public URL, or `undefined` for anything that isn't a page request (API routes, `/_next`, `.md` URLs, Markdown and RSC requests):

```ts title="proxy.ts"
import { NextResponse, type NextRequest } from 'next/server'
import { mdProxy } from '@affordances/md/next/proxy'
// your own rewrite: /package/@scope/name → the URL app/package/[pkg] answers, or undefined
import { collapse } from './site'

export const proxy = (request: NextRequest) => {
  const md = mdProxy(request)
  if (md.markdown) return md.next()

  const url = collapse(request.nextUrl)
  if (!url) return NextResponse.next()
  const response = NextResponse.rewrite(url)
  if (md.link) response.headers.set('Link', md.link)
  return response
}
```

A `Link` the proxy sets replaces the one `md()` sets for the same URL, rather than adding to it, and that includes an Affordances graph's `rel="affordances"` value. Set `md.link` only for the URLs `md()`'s rules miss, as above, or join the values yourself.
