`@afford/react` serves agents that run inside the browser, next to the person.

## AffordProvider

```tsx
<AffordProvider path={pathname} onDelta={() => router.refresh()}>
  {children}
</AffordProvider>
```

On mount, and whenever `path` changes, the provider fetches the page's graph from its own URL. When the browser supports WebMCP, it registers each available action as a tool:

| Tool field                      | From the descriptor    |
| ------------------------------- | ---------------------- |
| `name`                          | `name`                 |
| `description`                   | `description`          |
| `inputSchema`                   | `input`                |
| `annotations.readOnlyHint`      | `readOnly`             |
| `annotations.consequentialHint` | `expose === 'confirm'` |

A tool's `execute` doesn't call the server action directly. It POSTs to the page's Afford endpoint, the same way a headless agent would, so browser agents get the same `expose`, Origin, guard, and confirm checks as everyone else. The browser sends the person's cookies and the page's Origin, so session actions work.

After each call, the provider calls `onDelta`, reloads the graph, and registers the tools again, so tools that became available appear and ones that didn't go away. Unmounting unregisters everything.

WebMCP is read from `document.modelContext`, falling back to the earlier `navigator.modelContext`. Without either, the provider still loads the graph and does nothing else.

### Props

| Prop      | Type                                               | Description                                                                        |
| --------- | -------------------------------------------------- | ---------------------------------------------------------------------------------- |
| `path`    | `string`                                           | The current page's path and query. Change it on navigation.                        |
| `onDelta` | `(delta: Delta) => void`                           | Called after every call. In Next, `router.refresh()` re-renders server components. |
| `confirm` | `(message: string) => boolean \| Promise<boolean>` | Asked before a `confirm` action runs. Defaults to `window.confirm`.                |

### useAfford

Inside the provider, `useAfford()` returns `{ graph, call, lastDelta }`. `graph` is the page's graph, or `null` while it loads or when the page has none. `call(action, input)` calls an action the way a tool would, including the confirm step, and resolves to the delta. `lastDelta` is the most recent delta from any call, or `null`.

```tsx
'use client'

import { useAfford } from '@afford/react'

export const AgentStatus = () => {
  const { graph } = useAfford()
  if (!graph) return null
  const available = graph.actions.filter((action) => action.available)
  return <p>{available.length} actions available to agents on this page</p>
}
```

## Affordance

`<Affordance>` marks the element a person would use for an action, for agents that read the DOM:

```tsx
<Affordance action={addToCart} input={{ sku: variant.sku }}>
  <button formAction={addToCart}>Add to cart</button>
</Affordance>
```

It renders a `display: contents` wrapper with `data-afford-action="addToCart"` and, when you pass `input`, `data-afford-input` with the input as JSON. It doesn't register anything or change behavior.

In a server component, `action` is the real function from `defineAction`, and `<Affordance>` reads the name from it. In a client component, a server action arrives as a bare reference without its metadata, so pass the name instead:

```tsx
<Affordance name="addToCart">…</Affordance>
```

## Devtools

`<AffordDevtools />` from `@afford/react/dev` shows what agents see, on top of the page. Render it inside the provider, in development only:

```tsx
import { AffordDevtools } from '@afford/react/dev'

{
  process.env.NODE_ENV === 'development' && <AffordDevtools />
}
```

Press ⌥A (Alt+A) to toggle it. It outlines every `[data-afford-action]` control with its action's name: solid when the action is available, dashed with the reason when it isn't. It also shows the last delta.

[`@afford/lint`](/lint) warns when a control calls a server action outside an `<Affordance>`.
