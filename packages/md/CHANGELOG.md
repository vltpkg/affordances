# @affordances/md

## 0.5.0

### Minor Changes

- d9ab54e: Converter fixes for component-library HTML:

  - Links side by side are spaced even when one holds an empty block, as an avatar stack's fallback `<div>` does: `[Ann](…) [Bo](…)`.
  - A form without an `aria-label` or `aria-labelledby` gets no `**Form**` heading. What it already says, such as a card's title, stays in place.
  - On a `data-affordances-md="values"` form, a checkbox, switch, toggle or lone radio button gives its state as `on`, `off` or `mixed`, unchecked included: `- Keep logs (checkbox): off`. A checkbox used to read `(checkbox, selected)`, and nothing when unchecked.
  - Text isn't escaped where Markdown would only make it a link to itself: `tj@acme.dev`, `www.acme.dev` and `https://acme.dev` read as they are in paragraphs and table cells, as form values already did. Headings keep the escapes.
  - A code block keeps its language from `data-language` on its `<code>` or `<pre>`, or a `language-*` class on its `<pre>`, and its title from a `<figcaption>` before it in its `<figure>` or a `data-title` on what holds it, as rehype-pretty-code, Expressive Code and fumadocs render them.

- c110634: `createLlmsFullHandler`'s `pages` takes `{ url, title?, markdown }` as well as paths: `markdown` is a string or a function of the request, and the page is never rendered or fetched, so a site with a data layer skips the HTML round trip. Its links are made absolute and point at their twins, as a rendered page's are. Both run alongside the page renders, and a `markdown` function or an `append` that throws makes the file a `503`. `append` adds Markdown at the end of the file, with `createMdHandler`'s signature.

  Both llms files are the public site, whoever asks: `pages`, `sections`, a page's `markdown`, `append` and the `headers` option get a request with none of the visitor's headers, and a request that sends a `cookie` or `authorization` gets its copy `private, no-store`. Before, the caller's own request reached them and the file was still cached publicly.

- 62f3150: `createLlmsTxtHandler` takes `note`: Markdown that replaces what the plugin says after the summary (that every page is Markdown, where `llms-full.txt` is, and on an Affordances site how to read its graphs), or `false` for none. The site's `intro` now comes after that note, not before it, so `llms.txt` reads title, summary, note, intro, sections. The default line on `llms-full.txt` is now "For the full text in one file, see llms-full.txt", which stays true when `pages` leaves some out. A section takes `sections` of its own, rendered under `###` down to `######`; one nested deeper throws, naming it.
- 827e34c: `llms-full.txt` is never cached missing a page. A page that failed to render (a timeout, the `deadline`, a `5xx`, `408` or `429`, a fetch error, or a page still loading after its `timeout`) makes it a `503` with `Cache-Control: no-store` and `Retry-After`, so the next request renders it again. `llms.txt` still links such a page by its path and stays cacheable. `x-affordances-md-dropped` now counts failed pages only. A page left out by design (a redirect, another `4xx`, a response that isn't Markdown, a private render) leaves the file cacheable, and in development a private one is logged as an error.

  `createLlmsTxtHandler` and `createLlmsFullHandler` take `publicCache`, with `markdown.ts`'s values (a `cacheLife` profile or `{ revalidate, expire? }`) or `false`. The default is still an hour.

- 756cba1: `maxBytes` counts the HTML the converter keeps, not Next's Flight data. The handler takes each Flight push out of the page as it streams, reading it for its error rows, so a big `partialPrefetching` page (most of whose bytes are Flight data) is never held whole and converts with the default. The default is now 16 MiB of kept HTML (was 6 MiB of the whole page), and the whole response can be up to 8 times `maxBytes`; past either limit the page answers `413`, naming which.
- 07af5ad: On a route with `publicCache`, an anonymous request for the page's own URL with `Accept: text/markdown` gets a `307` to its `.md` twin, `private, no-store`, `Vary: Accept`, with a line naming the twin. Nothing is rendered, and the twin is what a CDN keeps, so agents that negotiate hit the cache too. Credentialed requests and routes without `publicCache` are unchanged, and the redirect's `Location` is relative, so it's right behind any proxy. `llms.txt` and `llms-full.txt` now read each page at its twin (at its own URL with `Accept` on a `literalMd` route), so they follow no redirect.
- f496f95: `@affordances/md` supports every Next 16 (`next: >=16`), and it's tested on a version matrix from 16.0.0 to the current canary. Where md reads something Next doesn't document, a Next that changes it gets private markdown or an error, never a public or wrong page:

  - A page whose Flight data has any error row (a boundary that caught an error, an `error.tsx`) keeps its status and is `private, no-store` with `x-affordances-md-uncached: error`, even on a route with `publicCache` or a page Next itself cached. `llms.txt` and `llms-full.txt` leave it out, as a private page, and stay cacheable.
  - A Next digest md can't read answers `502`, `private, no-store`, logged once per process. So a Next release that changes its digests shows up as 502s, never as wrong pages.
  - A page the handler couldn't reach at all (a refused connection, an unreachable origin) answers `502`, not `504`, which stays for a page that took too long. The body names only the page's path, never the origin, which can be an internal host; development adds the cause, in the body and the log.

- eb25387: `md()` no longer edits `tsconfig.json` when the config loads. When `.affordances/**/*.ts` isn't in its `include`, `md()` says the line to add, once per process. `affordances-md init` adds it, keeping the file's comments and formatting. `markdown.ts` works either way; the include is what lets `tsc` and `next build` check each one against its route. Development warnings that fired on every request (a cookie set on an opted-in page, a default export that returned nothing, a slot without a fill) are now said once per route per process. The `maxBytes` warning is said once per page.
- 89846d1: `markdown.ts` can export `notFoundMarkdown`, the route's 404 in Markdown. It runs whenever the route's page answered `404` through `notFound()`, before or after the shell streamed, so an agent gets the same body either way, with the default export's arguments. It returns a string, `{ markdown, title?, description? }`, or `undefined` for the page's own `not-found.tsx` as before. The answer is always `404`, `private, no-store`, and a request straight to the handler's URL never runs it. Typed as `NotFoundMarkdown<'/route'>`.
- ff68ad5: `mdProxy` gains three verbs and `@affordances/md/next/proxy` gains a function:

  - `md.request`: the page as a `NextRequest`, with the request's method, headers and cookies, for a gate that takes a request.
  - `md.rewrite(destination, init?)`: `NextResponse.rewrite`'s signature. A Markdown request gets the destination page's Markdown with `init.status`, `private, no-store`, varying on `Accept`; anything else gets Next's own rewrite.
  - `md.adopt(response)`: makes a third-party middleware's answer right for a Markdown request. Its redirect to a page on this site goes to that page's `.md`, its rewrite gives that page's Markdown with its status, and its `next()` goes on to the handler, with the cookies it set. Another origin, and any request that isn't for Markdown, get the response as it came.
  - `mdAliasPath(pathname)`: the app route URL a public URL renders through `md({ aliases })`, as the handler resolves it.

  The gate's own request headers (the ones it sets with `request.headers`, such as who the visitor is) reach the page's `markdown.ts`, fills and `append` in place of the client's, and a rewrite keeps its destination's query. A rewrite's page and status reach the handler on a request header carrying a token from `md()`, new on each build and kept in no file, which the route takes off the request before your code sees it. A header without it answers `500`, never the page unguarded, and a proxy without the token answers `500` rather than rewriting unverified.

- 2955f4e: `data-affordances-md="show"` keeps a panel people open on the page, such as a tab panel or an accordion's content, even when it's `hidden`. Each tab panel is headed by its tab's label, and its tab list is left out. Put it on Radix's, shadcn's or fumadocs' panel next to `forceMount`: `<TabsContent forceMount data-affordances-md="show">`. Without the marker, a hidden panel is still dropped like anything else people can't see.
- 7fd7e48: Markdown that stays private says why in `x-affordances-md-uncached`, on any route and in production too: `credentials`, `set-cookie`, `status`, `partial`, `error`, `gate`, `negotiated`, `invalid` or `private`. Markdown is `private, no-store` unless the route's `publicCache` or the page's own `Cache-Control` makes it public, so a page that sends none is private. A gate that sets a cookie for a signed-out visitor was visible only in development before.

### Patch Changes

- 188efc3: The converter finds the content root, empty tables and code-block titles in one walk each instead of re-walking the page per candidate, so big pages convert faster. Output is unchanged.
- 936ec3e: A page that renders its meta description under its `<h1>` says it once: the block right after the `#` heading is left out when its text is exactly the frontmatter's `description`. Without frontmatter it stays.
- 34fdf0e: Security: the llms handlers' site-index request never follows a redirect, so the `headers` option (a protection bypass, a token) never reaches the host it points to. A redirect there means no index.
- dacec5d: In `llms.txt` and `llms-full.txt`, a page's first heading names it only when its title goes on past a separator and a space: a page titled `Sign-in · Acme` whose heading is `Sign` keeps its title, rather than being named `Sign`.
- 6e78bdf: Security: `llms.txt` and `llms-full.txt` write a page's own title and description as plain text: one line, with the brackets and angle brackets that link and autolink syntax react to escaped. A title such as `evil](https://evil.test/phish) [x`, or a description with blank lines and a `## heading`, can no longer add a link or a section to the public files. Frontmatter is read line by line, so a `U+2028` in a value can't pass for a key of its own.
- cc29405: Without the Affordances graph (`withMd` on its own), `llms.txt` and `llms-full.txt` no longer ask for `/.well-known/affordances.json`: only an app `withAffordances` wraps has one, whichever wrapper runs first.
- 2c8fba5: Files in `public/` never get a Markdown twin. Under a root catch-all page, a link to `/openapi.json` stays as it is instead of pointing at `/openapi.json.md`, and no `public/` file gets a `Link` to a twin: a path has a `Link` exactly when it has a twin. A page named like a `public/` folder (`/docs/intro` beside `public/docs/`, or `/docs/v1.2` beside its images) keeps both. md() records `public/`'s files when the config loads, symlinked folders included, with a folder of thousands of files as one entry that keeps their extensions, so the list it passes to the handlers stays small.
- 98dbf95: Documented: the default export and every fill of one twin get the same `request` object, so a `WeakMap` keyed by it shares their data, and it's tested. `caching.mdx` notes that Next sets an app page's own `Vary`, replacing one from `next.config`, `proxy.ts` or `md()`.
- d6676bc: The frontmatter `title` is the page's `#` heading when the `<title>` is that heading in the site's template, such as `Authentication — Acme Docs` for `<h1>Authentication</h1>`, with the heading on either side of a `·`, `|`, `–`, `—` or `-`. Any other `<title>` stays as written.
- 11b45ca: A twin asks for its page uncompressed (`accept-encoding: identity`): it's a fetch from the server to itself, where gzipping the HTML only to unzip it again cost more than the bytes saved.
- 41ca3a7: `RouteArgs`, `PathParams` and `SegmentParams`, which `MarkdownModule` and `RouteParams` are built from, are exported, so the API reference names every type the public signatures use.
- ba9d42d: On a `data-affordances-md="values"` form, a field named `authorization`, `cookie`, `sid` or `signature`, or whose value is a bearer token (`Bearer …`) or a JWT, gives only its label, as other secret-looking fields do.

## 0.4.0

### Minor Changes

- cb2453a: `createLlmsTxtHandler`'s sections can carry prose: `intro` is Markdown under a section's heading, before its pages, and `pages` is optional, so a section can be prose alone. Its links are made absolute and point at their Markdown twins, as page links are.
- a5289b6: `export const publicCache` in `markdown.ts` lets a CDN keep a route's public Markdown: a `cacheLife` profile (Next's own, or one from `next.config`'s `cacheLife`) or `{ revalidate, expire? }` in seconds. The `.md` URL then gets the `Cache-Control` Next sends for a page cached that long (`'hours'` is `s-maxage=3600, stale-while-revalidate=82800`), for slot routes, default exports and pages converted from their HTML. It applies only to an anonymous, complete `200` at the `.md` URL, with no credentials from the request or the `headers` option and no cookie set by the page; anything else is exactly as before. That public view is the same for every visitor: for such a request the page is rendered, and the `markdown.ts`, its fills and `append` run, with none of the visitor's headers (language, user agent, country). A profile name that isn't one, or a field that isn't `revalidate` or `expire`, fails `tsc` against the profiles, custom ones included, and in development the server names the file and the valid values; until it's fixed, the route isn't cached.

### Patch Changes

- 0beaa59: A route handler outside `app/api/` (`/llms.txt`, `/openapi.json`, `/og/[slug]`, or a Next metadata route such as `sitemap.ts`), asked for with `Accept: text/markdown`, is passed through as it is, with the caller's own headers, rather than fetched as a page to convert. `md()` records each one when it scans `app/` and ranks them with its pages as Next does, so a static page beside a dynamic route handler (`/og/about` beside `app/og/[slug]/route.ts`) is still a page, and a route handler's path is never twinned in a link.
- 3a9cf46: Big pages convert faster. Next's flight data is dropped before the page is parsed, the head is read in one pass, and a filled slot's own content is no longer converted only to be replaced. On a 4 MB page with `partialPrefetching`, its `.md` twin went from 6.3× the page's time to 3.6×.
- a952db2: Security: in 0.3.0, a page's own content could redirect its `.md`. A raw copy of Next's redirect tag (`<meta id="__next-page-redirect" http-equiv="refresh">`) in content a page renders as HTML (a README, a user's post) made the handler answer a redirect, to another origin too. Now only the error row Next writes into the page's Flight data counts, which a page's content can't write. The same rule decides the status of a streamed `notFound()`, `forbidden()` or `unauthorized()`.
- 6384fb0: Fixed: the frontmatter `title` of a `markdown.ts` page, and its `llms-full.txt` heading, took its first `# ` line as written, link syntax and URL included (`[Methodology](https://…)`). It's now the heading's text: a link keeps its text, and a URL shown as itself is dropped. The page's own Markdown is unchanged.
- 210e88f: Fixed: a list or paragraphs inside a `<dd>` ran into the term's line; they're now blocks after it. Blocks stacked in a table cell (`<div>`s, `<p>`s, or an element with a `block`, `flex` or `grid` class or `display`) ran together; they're now spaced.
- cb2453a: Fixed: relative links in `createLlmsTxtHandler`'s `intro` were printed as written, so they broke for an agent reading `llms.txt` away from the site. They're now absolute and point at their twins, as page links are.
- 2829b39: `llms.txt` and `llms-full.txt` render their pages 8 at a time instead of all at once (`concurrency` sets it), and each page's `timeout` runs from its own request. The whole file has a `deadline`, 25 seconds by default; pages not rendered by then are left out and counted. A page they leave out (a timeout, a status, a private render) is no longer silent: the files carry an `x-affordances-md-dropped` count, and in development the server logs each page and why. `llms-full.txt` heads each page with its title, falling back to its first heading when that's how the title starts or when the title is shared across pages.
- 45ddd21: A page larger than `maxBytes` answers `413` saying what to change: its limit, and the line that raises it in the md route (`export const GET = createMdHandler({ maxBytes })`). The server logs the same, with the page's path, so a page that grows past the limit is caught. The setup docs now show replacing `init`'s one-line route to set `maxBytes` and `timeout`. The default stays 6 MiB.
- a952db2: Fixed: on Next 16.3, a prerendered page whose `<Suspense>` child calls `notFound()`, `forbidden()` or `unauthorized()` while it's built is sent as a `200`, and converted as one. The handler now reads the error from the page's Flight data, where Next writes its digest as an error row (`NEXT_HTTP_ERROR_FALLBACK;404`) that a page's own content can't write. It answers `404`, `403` or `401`, `private, no-store`, and `llms` leaves the page out, as on 16.4.
- 3c1ce48: Fixed: a `notFound()`, `forbidden()` or `unauthorized()` that runs after a page's shell has streamed (or, with `cacheComponents`, anywhere under a `<Suspense>`) converted as a `200` with the shell's markdown. The handler now answers `404`, `403` or `401`, `private, no-store`, as it does for one thrown in `markdown.ts`. `readPage(html).fallback` gives the status.
- 29f8cac: The line `md()` prints when it adds `.affordances/**/*.ts` to `tsconfig.json`'s `include` is now a warning that starts with the change (`Updated tsconfig.json: …`) and says to commit it, so a build changing a tracked file is hard to miss.
- 4d5bea5: Fixed: a file named `markdown.ts` next to a page that has none of a `markdown.ts`'s exports (a helper with only a named export) broke `tsc` with a bare `TS2322` in `.affordances/md.ts`. `md()` now leaves it out and says so when the config loads. `tsc` stops with the same message: the file, what it exports, the exports a `markdown.ts` uses, and to move it out of `app/` or rename it if it's for something else.

## 0.3.0

### Minor Changes

- 89a26fd: `md({ aliases })` maps public URL shapes your `proxy.ts` or rewrites send to an `app/` route, in Next's rewrite syntax: `{ '/package/@:scope/:name/:rest*': '/package/@:scope%2F:name/:rest*' }`. Those URLs then get their `Link` header, twin links in the Markdown, and their route's `markdown.ts`, with `params` exactly as `page.tsx` gets them (`{ pkg: '%40babel%2Fcore' }`, still encoded). `literalMd` stays in public URL space: list an aliased URL's public shape there. Each alias is checked when the config loads: a destination no page answers throws, quoting the alias and naming the nearest pages. Aliases match as strictly as Next routes a page, against the URL that was requested, and a request made straight to the handler still never runs a `markdown.ts`.
- b5415c2: `mdProxy(request)` from `@affordances/md/next/proxy` gives a gated `proxy.ts` one object: `md.page`, the page the request is for whether it asks for HTML or Markdown (`/compare.md` is `/compare`), so every gate runs on the same URL; `md.markdown`; `md.redirect(url, status?)`, which sends a Markdown request to the target's `.md` when it's on this site (privately, varying on `Accept`) and any other target as a plain redirect; `md.next(init?)`, which sends a Markdown request to the handler and lets any other through; and `md.link`. The docs' gate-first recipe is now three lines around it. `isMdRequest`, `mdRewrite` and `mdLink` are unchanged.
- adaef12: `markdown.ts` can export `slots`, which fill the page's `<AgentSlot name>`s instead of replacing the whole page: `export const slots = { readme: async ({ params }) => … } satisfies Slots<'/package/[pkg]'>`. The default export still runs first, and anything but `undefined` is the whole page. Otherwise the page renders (so its redirects, `notFound()` and layout checks run before any fill), then only the slots it rendered once, where they reach the Markdown, run, together and in the visitor's request; the rest converts as usual. A slot's own render condition doesn't gate its fill (user HTML can carry a marker), so each fill authorizes its own data, as `markdown.ts` does. A filled page is `private, no-store`, a fill's `notFound()` or `redirect()` answers for the whole page, and a request straight to the handler runs no fill. In development the handler warns, naming the route's `markdown.ts`, about a fill with no slot, a slot with no fill, a name used twice, and a fill that returned nothing.
- ba82656: Slots and links in markers:

  - `<AgentSlot name>` marks a part of the page that `markdown.ts` fills, while the rest of the page converts from its HTML. A name rendered twice is filled nowhere.
  - `readPage(html)` reads a page once: its `slots` lists the page's slots, `markdown(slots)` fills them, and `redirect` is a `redirect()` Next streamed into it. `htmlToMarkdown(html, { slots })` does it in one call.
  - Links in `<AgentText md>` and in a slot's fill are made absolute and pointed at their Markdown twin, like the page's links.

  Fixed: a block `<AgentText>` inside a paragraph ran into the paragraph's text, which was broken Markdown. It's now its own block between the paragraph's halves.

- 5166b33: `MarkdownArgs<'/route'>`, `Markdown<'/route'>` and `Slots<'/route'>` type `params` from the route string, as `PageProps` does for `page.tsx`: `[x]` is a `string`, `[...x]` a `string[]`, `[[...x]]` a `string[]` or left out. `params` stays a plain object, still URL-encoded, and without a route the types are 0.2.0's. The arguments also carry `route`, the `app/` route the handler matched (`'/package/[pkg]'`); it's optional in the type, so arguments built by hand, as in a 0.2.0 unit test, still type-check. The generated `.affordances/md.ts` checks each `markdown.ts` against its own route, so a wrong route string fails `tsc`, even one whose params look the same; TypeScript skips `.affordances/` unless `include` names it, so `md()` adds `".affordances/**/*.ts"` to `tsconfig.json`'s `include`, as Next adds `.next/types`: only that array, keeping comments and formatting, and only when the file has its own `include` without it. When it can't edit safely (the file can't be read or parsed, `include` is inherited, or the file is read-only), it warns with the line to add, and never stops the config from loading.

  A `markdown.ts` can use Next's own `notFound()`, `forbidden()`, `unauthorized()`, `redirect()` and `permanentRedirect()`: they answer `404`, `403`, `401`, or a `307`/`308`: to the target's `.md` when it's a page on this site, and to the target as it is otherwise (another origin, an API route, a route handler or a file), all `private, no-store`.

### Patch Changes

- 6c275d2: Converter fixes:

  - An `<AgentText>` inside a link keeps the link.
  - Links named only by `aria-label`, links in wrappers and text in a flex or grid gap are spaced.
  - Sortable table headers keep their button's label.
  - Forms read ARIA switches, checkboxes, radios, toggles and selects, follow `aria-labelledby`, are named by their `aria-label`, `aria-labelledby` or first heading, keep their text in page order, and no longer escape `@` and `:` in values.
  - A form's tables and definition lists keep their shape, with each field written where it is. A form named by its own `<legend>` or `<label>` keeps that name as its title.
  - Fields and links are named as a screen reader names them: a switch, checkbox, radio or toggle button by its own words, and a link with nothing in it by its `aria-labelledby`.
  - A heading, caption, summary or term whose only text is a button (an accordion's header) reads the button's text.
  - A name never reads what's hidden from people or what carries a value (a textarea, an option, an output, meter or progress, an editor), and an editor (`contenteditable`, `role="textbox"`) is left out like a textarea.

- 150da63: A page that calls `redirect()` after its shell has streamed now gives a 307 (or 308 for `permanentRedirect()`) to the target's `.md`, instead of a 200 with only the shell. The handler reads the redirect Next streams into the page, and applies the same rules as for any other redirect: same-origin targets become their `.md`, another origin is passed on as it came, and a credentialed or negotiated response is `private, no-store`.

  An RSC request that also asks for Markdown, and any page or file the handler passes through, no longer 500s when the app's `proxy.ts` rewrote the page: the handler drops Next's `x-middleware-*` headers, which a route handler can't send.

## 0.2.0

### Minor Changes

- 302afce: md: a form marked `data-affordances-md="values"` lists its fields' current values, never a hidden, password, or secret-looking field's. The converter also drops skeleton tables (no cell text, or a header over empty rows), merges a run of the same link into one, and spaces inline elements laid out side by side with CSS gaps (`express 5.3.0`).
- c07e88e: `md({ literalMd })` takes routes whose pages' own URLs can end in `.md`. There the handler fetches the exact URL first: the page wins if it answers with anything but a 404 (converted for a Markdown request, passed through as HTML otherwise), and a 404 makes the `.md` the twin suffix. Twin URLs are unchanged.
- 88e486b: `markdown.ts` next to a `page.tsx` gives that route's markdown from its data, without rendering the page. It returns a string, `{ markdown, title?, description? }`, a `Response`, or `undefined` to fall back to converting the HTML. `md()` finds the files, generates `.affordances/md.ts`, and aliases the new `@affordances/md/routes` export to it.

  The page's own auth checks don't run for `markdown.ts`, and `proxy.ts` runs only once, on the requested URL, so `markdown.ts` must use fetchers the API authorizes. **If you used 0.1.0's proxy recipe, which returned early for markdown requests (`if (isMdRequest(request)) return NextResponse.next()`), remove that skip, or move it after your auth gate, before adding a `markdown.ts`.** Otherwise nothing gates it. The handler never runs `markdown.ts` for a request made straight to its own URL, or for a URL Next wouldn't route to the page (another letter case, percent-encoded or empty segments). `llms.txt` and `llms-full.txt` fetch each page at its public URL with `Accept: text/markdown`, as an anonymous visitor.

- bfe7523: New `@affordances/md/next/proxy` entry with `mdRewrite`, `mdLink`, `isMdRequest`, `mdPagePath` and the rule constants, for a `proxy.ts`. It holds only the matching, so a proxy that imports it bundles neither the converter nor any `markdown.ts`. `@affordances/md/next` re-exports the same functions, so existing imports keep working.
- c07e88e: md: `mdLink(request)` gives a proxy.ts the `Link` alternate for a page's public URL, for routes `md()`'s header rules can't match (a URL the proxy rewrites, like a scoped package's). The rewrites and `mdRewrite` also leave a request with Next's `_rsc` param alone, like one with the `RSC` header.
- 302afce: md: a page still streaming at the handler's `timeout` is converted as far as it got, not answered with a 504. Unresolved boundaries keep their fallback, the markdown ends with a note, and the response is `private, no-store` with `x-affordances-md-partial: 1`. Streamed content also resolves past ten boundaries (React's ids are hex), into table rows, and through React's `$RR`, `$RS` and external-runtime reveal forms.

  The `headers` option's `cookie` and `authorization` now apply only to a request that sent neither: a signed-in person's markdown renders with their own credentials alone, never as the service account, and an anonymous request still renders with the service's. A visitor with any cookie, even an unrelated one (analytics, consent), is rendered without the option's credentials: on a protected preview whose access rides on them, that visitor's markdown may be the protection or login page. A bypass in its own header, such as `x-vercel-protection-bypass`, always applies, so use one of those for protection bypass. Both are `private, no-store`.

- 302afce: The handler's markdown links the site's own pages to their markdown twins (`/blog/post` → `/blog/post.md`, query and hash kept), so an agent following a link stays in markdown. Opt out with `createMdHandler({ linkTwins: false })`. `htmlToMarkdown` takes the hook as a new `link` option.

### Patch Changes

- 4d1a09b: Converter hardening from the security audit: a page's own `data-affordances-md-text` is no longer output verbatim; links keep only their text unless they're `http`, `https`, `mailto`, or `tel` (checked as a browser parses them, so `java&#10;script:` is caught), and images need `http` or `https`; content hidden with an inline `display: none` or `visibility: hidden` is dropped; a field's placeholder or `name` is never its label; and `usePageMarkdown` refuses a path on another origin.
- 4d1a09b: md: a form's label or legend no longer carries the value of a control inside it. A `<label>` wrapping a `<textarea>` gave its text (`Key sk-…`), and one wrapping a `<select>` gave every option.
- 302afce: On a `literalMd` route, a link in the handler's markdown to a page whose own URL ends in `.md` points at that page's twin (`/x/readme.md` → `/x/readme.md.md`), like any page's, instead of being left as the HTML page.
- c07e88e: The markdown handler passes a client navigation (`RSC` header) through as the page's own RSC response instead of converting it, so a `proxy.ts` using `mdRewrite` no longer turns an RSC fetch that asks for `text/markdown` into markdown.
